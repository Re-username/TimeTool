# Журнал разработки TimeTool

Формат: дата — что сделано, ключевые технические решения и причины. Ведётся по релизам.

## 2026-11-17 — v1.0.0 → v1.3 (первый день)

- **v1.0.0**: каркас .NET MAUI Blazor Hybrid (один проект → Windows exe + Android APK).
  Страницы: таймер, секундомер, калькулятор времени (сумма интервалов), часы
  с ручной сверкой NTP. Сборка через SFX-лаунчер (net472-stub + zip ресурсом,
  распаковка в `%LOCALAPPDATA%\TimeTool\App` по маркеру version.txt).
- **v1.1**: события с повторяемостью (день/неделя/месяц/год) и «умными»
  напоминаниями (lead + показ пропущенных при запуске, окно сутки, ключи
  `_fired` в localStorage). Копирование отсчёта markdown для Obsidian.
- **v1.2**: трей (сворачивание при закрытии), виджеты Rainmeter (позже удалены),
  повторы, конвертер единиц, автосверка NTP каждые 15 мин.
- **v1.3**: системные уведомления (toast), иконка трея из exe, аудит исключений.

## 2026-11-17 — v1.4.0 → v1.4.3 (вечер)

- **v1.4.0**: автозапуск с Windows (реестр Run), кастомный звук таймера
  (файл ≤8 МБ, base64 в WebView), balloon-уведомления.
- **v1.4.1**: звук выбирается через проводник, отдельный звук для каждого
  события, конвертер выровнен.
- **v1.4.2**: при первом сворачивании в трей — подсказка balloon «где искать значок».
- **v1.4.3**: значок трея на выделенном потоке с собственным циклом сообщений
  (на главном потоке WinUI значок замирал при сворачивании).

## 2026-11-18 — v1.4.4 → v1.4.8 (трей и Rainmeter)

- **v1.4.4**: трей перестал пропадать — глобальный класс окна `STATIC` вместо
  собственного WNDCLASS (свой класс умирал вместе с создавшим потоком).
- **v1.4.5**: баллуны молча терялись → `NIM_SETVERSION` (v4) сразу после
  `NIM_ADD`. Логирование toast в файл, тестовый хук `TIMETOOL_TEST_BALLOON`.
- **v1.4.6**: перенос выходных в событиях (зарплата, выпавшая на сб/вс → пт/пн);
  локальный HTTP-сервер на 127.0.0.1:47777 для Rainmeter (/events.txt|json,
  BOM для WebParser — иначе кириллица ломалась в ANSI); скины WebParser/WebView2
  в integrations/Rainmeter.
- **v1.4.7**: клики трея под version 4 (NIN_SELECT/WM_CONTEXTMENU — левый клик
  больше не падает); таймер живёт в TimerEngine и не сбрасывается между
  вкладками; регэксп скина PCRE + состояние «нет событий».
- **v1.4.8**: трей как в filechat (маскировка lParam, ExactSpelling у W-функций
  P/Invoke, top-level окно для меню, dispatcher-маршаллинг), таймер в Rainmeter
  (/timer.txt + /timer.json), форма добавления событий.
- Отдельно: `UpdateRate=1` у WebParser — по умолчанию обновлялся раз в 600 тактов.

## 2026-11-21 — v1.4.9 (события: заметки, редактирование, «наступило»)

Жалобы: однократные события после наступления показывали «-388 мин», никакого
сигнала о наступлении (ни баннера, ни звука, ни подсветки), на вкладке «Часы»
событий не видно.

- **Заметки**: `EventItem.Note`, поле в форме добавления, вывод в карточке,
  баннере, markdown-копировании и Rainmeter JSON.
- **Редактирование**: кнопка «Изменить» в карточке — панель переходит в режим
  правки (все поля + заметка), «Сохранить»/`Store.UpdateAsync`.
- **Сигнал о наступлении — всегда**: раньше напоминание зависело от настройки
  lead (выкл = тишина). Теперь два независимых срабатывания на наступление:
  «due» (баннер+звук+toast/балун трея) и «lead» (предварительное, только если
  настроено), ключи `_fired` с суффиксами `:due`/`:lead`.
- **Красные состояния**: `IsHappening` (±2 мин от наступления — пульсирующая
  рамка + бейдж «наступило!»), `IsOverdue` (однократное просроченное — рамка и
  «прошло N назад»). `FormatLeft(out overdue)` — отрицательных значений больше
  нет ни в UI, ни в Rainmeter.
- **Часы**: секция «События» под циферблатом — ближайшие 2 дня, живой отсчёт,
  красные состояния; подписки на Store с отпиской в `Dispose()` (утечка при
  навигации).
- **Rainmeter**: `Note`, `Happening`, `Overdue` в /events.json; «прошло … назад»
  в /events.txt.

### Потери данных при деплое (урок)

При ручной пересборке SFX папка `%LOCALAPPDATA%\TimeTool\App` была удалена
вместе с профилем WebView2 — **localStorage событий пользователя потерян**
(4 события, восстановлены вручную). Причины сложились: ручная сборка правила
`tools/sfxstub/Program.cs`, а собирала копию `build/sfx/` (старая константа
Version → стаб не переизвлекал приложение → проверялась старая версия, что
сбило с толку и привело к «чистке»). Правила: править то, что собирается;
перед удалением папки приложения — помнить, что данные WebView лежат рядом
с exe; извлечение SFX падает молча, если приложение запущено (смотреть
`sfx.log` рядом с App).

### Технические детали

- В Blazor-методе нельзя использовать `_` и как discard-параметр, и как
  discard-присваивание (`_ = Task`) в одном scope — CS0029.
- Старый экземпляр приложения держит порт Rainmeter — новый молча уходит на
  следующий порт; проверять, КТО отвечает на 47777 (данные могут быть от
  старой версии, что и наблюдалось: «-416 мин» после фикса).

### Проверка обновлений (дополнение к v1.4.9)

- `Services/UpdateChecker` — singleton, фоновая проверка
  `api.github.com/repos/Re-username/TimeTool/releases/latest` (6 с таймаутом,
  UserAgent обязателен — GitHub без него режет). Сравнение версий Major.Minor.Build.
- Версия приложения берётся из AssemblyInformationalVersion (ApplicationDisplayVersion)
  — больше не расходится с релизом.
- Баннер «Доступна новая версия» (Скачать/Позже) + строка версии в справке
  («Версия 1.4.9 · актуальная / доступна X»).
- Релиз v1.4.9 опубликован на GitHub (SFX exe + APK).
